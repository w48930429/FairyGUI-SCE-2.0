# ADR 0002: 战役流程采用服务端状态机 + Typed Message

## 状态

提议中（本 change 内落地后改为 accepted）

## 背景

AutoArmy 当前已有服务端权威战斗和快照广播，但玩家可操作流程缺少统一控制。  
若继续以分散逻辑直接处理 UI 点击，将出现以下风险：
- 重复开战或并发升级导致状态竞争
- 客户端与服务端进度不一致
- 后续接入持久化仓储时耦合过深

## 决策

采用“服务端状态机 + typed message”作为战役流程基础架构。

状态机：
- `Idle`
- `InBattle`
- `ResultPendingConfirm`

消息协议：
- 进度查询、开战请求、升级请求、结算确认、结果回推均使用强类型消息
- 统一错误码返回非法状态与业务拒绝原因

## 结果

正向效果：
- 流程边界明确，便于测试和回归
- 客户端只做交互与渲染，职责清晰
- 后续替换持久化实现时可保持消息与状态机不变

代价：
- 初期消息 DTO 和处理器数量增加
- 需要补充状态机相关测试用例

## 备选方案

1. 客户端本地状态机 + 服务端弱校验  
被拒绝：会增加不同步风险，不符合服务端权威原则。

2. 无状态请求，依赖每次请求即时判断  
被拒绝：逻辑分散，难以保证战斗中/战后的流程一致性。
